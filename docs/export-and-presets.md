# Word 导出与教学预设：实现说明与配置要点

本文件对应三个功能：备课工坊的 **Word（.docx）导出**、第三步右侧的 **学情与条件预设**、
以及贯穿全站的 **辅助素材层两张表**（知识点映射与知识卡）。三者都在 `src/` 内有唯一数据源/唯一实现文件，
本文件只做索引与约束说明，不重复代码。

| 功能 | 唯一实现文件 | 界面入口 |
| --- | --- | --- |
| Word 导出 | `src/lib/exportDocx.ts` | 工坊第四步「生成方案」→ 导出抽屉 →「下载 .docx」 |
| 教学预设 | `src/data/teachingPresets.ts` | 工坊第三步「定课程与学情」→「学情预设」区块 |
| 学科 ↔ 知识点映射 | `src/data/subjectPoints.ts` | 资源库 / 学科总览 / 课程地图 / 工坊第二步 |
| 知识点卡 | `src/data/knowledgeCards/*.ts` | 资源库「知识点卡」→ 卡片详情页 |
| 全站数字 | `scripts/verify.mjs`（`npm run verify`） | 不在界面出现，仅作提交前校验 |

**口径前提**：本平台是**《人类与社会》课程教学辅助平台**，课程是主体。《人类与社会》的十章 73 个知识点
构成内容主线，学科是**迁移落点**——知识点落到哪门课的哪个教学内容，由 `subjectPoints.ts` 逐条登记。
民俗只是第 7 章里的一类内容，不是全站基调。导出的文档、界面的层级顺序、文案措辞都按这个口径组织，
改动时请保持；信息架构的完整说明见 `docs/information-architecture.md`。

## 一、Word 导出

### 1.1 实现方式

浏览器端生成，不经过服务端：

- 依赖 `docx@9`，**动态导入**（`await import('docx')`），单独成一个 chunk，不进首屏包。
- 构建产物是 OOXML 压缩包，由 `Packer.toBlob()` 直接产出 `Blob`，再用 `downloadBlob()` 触发下载。
- 因此站点可以纯静态托管，无接口、无密钥、无并发限制。

### 1.2 导出范围（边界写在 `exportDocx.ts` 里，不靠调用方自觉）

| 层 | 模块 | 处理方式 |
| --- | --- | --- |
| 恒含 | 课程信息表 | **学科在首行**；随后 教学内容 / 辅助知识点 / 所属章节（借用时才出现）/ 教学素材 / 学段 / 课时 / 教学风格 / 学情预设 / 生成方式；有则出，空值落 `—` |
| 恒含 | 教案正文十节 | 一～十编号固定，不因可选项增减而错位 |
| 恒含 | 教学尺度提醒 | 仅当 `plan.caution` 存在（信仰类民俗等）时插入，位于信息表之后、正文之前 |
| 恒含 | 页眉 / 页脚 / 文末口径声明 | 页眉写平台名与课程主题；页脚为 Word 域；文末声明**教学主体为本学科内容**，知识点与民俗仅作辅助 |
| 可选·默认开 | 为什么这样配 | `options.rationale`；三条（学科这一侧 / 辅助这一侧 / 两者怎么接上）。无 `rationale` 数据时即使开启也不出 |
| 可选·默认开 | 教学素材清单 | `options.materials`；优先取 `plan.materialIds`，无则回退到民俗自带素材；只列条目（名称 + 类型 + 用法），**最多 24 条**，不内嵌图片与音视频 |
| 可选·默认关 | 知识要点摘录 | `options.cardDigest`；按 `plan.pointIds` 取 `cardOfPoint()`，摘出所借知识点的知识卡要点。零借用时输出一句「本课未借用辅助知识点，故无知识要点摘录」而不是空标题 |
| 永不进入 | 站点外壳与状态 | 侧栏与底部标签栏、页头按钮、收藏与草稿状态、屏幕专用样式（`@media print` 那套）、纹样矢量图 |

**信息表的口径顺序不能乱**：学科必须在第一行、辅助知识点在其后。这条顺序是"学科为主、知识点为辅"
在交付物上的唯一体现，也是导出文档里最容易被看见的地方。

**关于附件**：站内的"素材"是条目而非文件。导出只做**清单式引用**（名称 + 类型 + 用途 + 占位标记），
不打包二进制，也不把纹样 SVG 转成位图塞进文档——否则 Word 里会出现无法印刷的大色块，且文件体积不可控。
需要真图片时，由教师按清单自行插入本校素材。

**关于附录编号**：附录序号按"实际启用的项"顺延（附录一 / 附录二…），关掉一项不会留下空号。

### 1.3 文件命名

模板：`{主题}_{学段}_{学科}_{课时}_{日期}_{时刻}.docx`

| 变量 | 取值 | 示例 |
| --- | --- | --- |
| `{主题}` | 教师自拟的课程主题；为空回落「学科备课教案」 | `一张纸的旅行` |
| `{学段}` | 年级段，去空格便于按文件名排序 | `3-4年级` |
| `{学科}` | 所选学科原名 | `艺术` |
| `{课时}` | 40 分钟记 1 课时 | `1课时` |
| `{日期}` | YYYYMMDD | `20261104` |
| `{时刻}` | HHmm | `1822` |

清洗规则（`clean()`）：`\ / : * ? " < > |` 与换行制表符一律转 `_`，去掉空白，连续 `_` 合并，
单段最长 40 字（学段/学科/课时段 8 字）。带分钟级时间戳是为了同一主题反复导出不互相覆盖。

**文件名用学科、不用章节**，这是有意的：章节来自辅助层，教师换了借用素材不该导致同一份教案换个文件名。
学科是教师自己的归属，稳定。

完整示例：`一张纸的旅行_3-4年级_艺术_1课时_20261104_1822.docx`

### 1.4 排版规范

规范集中定义在 `exportDocx.ts` 的 `DOCX_STYLE_SPEC`，界面抽屉直接渲染同一份常量，
不存在"文档写一套、代码做一套"的漂移。

| 项 | 取值 |
| --- | --- |
| 纸张 | A4（210 × 297 mm），纵向 |
| 页边距 | 上 25.4 / 下 25.4 / 左 30 / 右 25 mm（twips：1440 / 1440 / 1701 / 1417） |
| 页眉页脚距边界 | 12.7 mm（720 twips） |
| 标题字体 | 黑体；西文 Arial |
| 正文字体 | 宋体；西文 Times New Roman |
| 文档标题 | 22pt（二号）加粗居中，段后 5pt，`outlineLevel` 不参与 |
| 一级标题「一、二、三…」 | 16pt（三号）加粗，段前 14pt / 段后 6pt，`keepNext` 与下段同页 |
| 二级标题（教学重点/难点等） | 14pt（四号）加粗，段前 8pt / 段后 4pt |
| 正文 | 12pt（小四），1.5 倍行距，首行缩进 2 字符（480 twips），两端对齐，段后 3pt |
| 列表项 | 12pt，悬挂缩进 14pt，段后 2pt |
| 表格内容 | 10.5pt（五号）；表头黑体居中，正文宋体左对齐，垂直居中 |
| 页眉页脚 | 9pt（小五）灰色 |
| 页眉内容 | 居中「乡音课坊 · 小学教师备课辅助 \| 课程主题」，下加细线 |
| 页脚内容 | 居中「第 X 页　共 Y 页」，`PageNumber.CURRENT` / `TOTAL_PAGES` Word 域；打开文档时自动更新，无需按 F9 |

段落样式统一注册在 `styles.paragraphStyles`（`DocTitle` / `Center` / `H1` / `H2` / `Body` /
`ListItem` / `TableText` / `Note` / `Gap` / `GapSm`）。**改字号改这里，不要在每个 Paragraph 上逐处写**。

### 1.5 验收方法

导出的 .docx 是标准 zip，可以解包验真，不靠肉眼：

```bash
# 1. 在工坊生成方案 → 导出 Word → 下载
# 2. 改名为 .zip 解包
Expand-Archive -Path plan.zip -DestinationPath out -Force

# 3. 核对关键项
#    word/document.xml  → 正文段落、表格数、w:sectPr、字体与字号
#    word/styles.xml    → Body 样式的 w:line="360"、w:firstLine="480"、w:jc="both"
#    word/header1.xml   → 平台名、课程主题、下框线
#    word/footer1.xml   → PAGE / NUMPAGES 域
```

已核验过的基线：25.4mm 边距（`w:top="1440"`）、A4（`w:pgSz w:w="11906" w:h="16838"`）、
正文 12pt + 1.5 倍行距 + 首行缩进、页眉页脚域齐备、正文十节与附录顺序正确。

**导出回归的三条必查**（每次动 `exportDocx.ts` 都过一遍）：

- [ ] 信息表首行是**学科**，第二行是教学内容；借用知识点时"辅助知识点""所属章节"两行同时出现，不借时两行同时消失
- [ ] 走「零辅助素材」路径（只选学科、不借知识点与民俗）能正常导出，且不出现"本课未借用"之外的残句
- [ ] 附录编号连续，关掉「为什么这样配」后剩下的附录从"附录一"开始

### 1.6 常见改动点

| 想改什么 | 改哪里 |
| --- | --- |
| 加/删一个附录 | `buildPlanDocx` 里 `appendix` 段，配合 `nextLabel()` 自动编号 |
| 改字号、行距、缩进 | `styles.paragraphStyles` 对应样式；同时更新 `DOCX_STYLE_SPEC` |
| 改页边距 | `buildPlanDocx` 的 `properties.page.margin` |
| 改页眉文字 | `sections[0].headers.default`（注意与 `DOCX_STYLE_SPEC` 的页眉行同步） |
| 改文件名结构 | `FILENAME_TEMPLATE` + `FILENAME_VARS`（界面会同步显示） |
| 改信息表行序 | `kvTable([...])` 的数组顺序；**学科必须保持第一行** |
| 加封面页 | 新增 `section` 并设 `titlePage: true`，正文部分另起一节 |

## 二、学情与条件预设

### 2.1 分类方式

按**「教师备课当天就能确认的事实」**分五类，不按教育学理论分类。每类只回答一个问题，
且互不重叠——同一条预设只归属一类，避免教师在两个分组里看到意思相近的条目。

| 分组 | 回答的问题 |
| --- | --- |
| 学生基础 | 学生已经具备什么、缺什么（可观察的学力与经验） |
| 学生构成 | 班里有哪些差异需要照顾（人的差异） |
| 课堂条件 | 设备、场地、班额、时间这类当天改不了的硬约束 |
| 教学资源 | 这节课能调用的材料、人力、场地（决定活动上限） |
| 课堂管理 | 组织与安全上的风险点（决定活动的收放方式） |

前两类描述"学生"，后三类描述"课怎么落地"。教师的实际使用顺序通常是：先扫后三类确认活动可行性，
再回头看前两类调难度。

### 2.2 覆盖范围

5 类共 **32 条**：

| 分组 | 条数 | 覆盖内容 |
| --- | --- | --- |
| 学生基础 | 8 | 基础强弱、动手经验、阅读量、民俗生活经验、预习习惯、书写速度、方言表达 |
| 学生构成 | 7 | 少数民族、随迁子女、复式班、特殊需要、发言积极性、留守儿童、转学新生 |
| 课堂条件 | 8 | 投影、空间、班额、课时、材料、网络、座位固定、合用教室 |
| 教学资源 | 5 | 实物教具、校园考察、家长志愿者、跨学科协同、图书与多媒体 |
| 课堂管理 | 4 | 纪律、分组熟练度、工具安全、不占用课间 |

**选择上限 8 条**（`ISSUE_LIMIT`）。超过之后各条适配建议开始互相削弱——例如同时选
「基础较薄弱」与「基础较好」，两条会给出方向相反的要求，教案反而失真。

### 2.3 生效机制

预设不是标签，三条通道都会真实改写教案：

```
IssuePreset.adapt ──┬─→ 教案「十、教学提示与反思」
                    └─→ AI prompt 的「学情与课时」段落
IssuePreset.prep  ──┬─→ 教案「三、教学准备」清单
                    └─→ AI prompt（同上）
```

因为正文与 prompt 都带上了，AI 生成的教案与 Word 导出自然都能反映预设。

### 2.4 维护与扩展

`src/data/teachingPresets.ts` 是**唯一数据源**，改动只动这一个文件，
界面、AI prompt、Word 导出全部自动跟随。

| 操作 | 做法 | 注意 |
| --- | --- | --- |
| 新增条目 | 往 `ISSUE_PRESETS` 追加 `{ id, label, group, adapt, prep? }` | `id` 全局唯一且**不要复用**——已保存方案按 id 回查 |
| 修改文案 | 直接改 `adapt` / `prep` | 历史方案下次打开即显示新文案 |
| 删除条目 | 从数组移除 | 旧方案里残留的 id 会被 `issuesByIds` 静默忽略，不会崩溃 |
| 新增分组 | `ISSUE_GROUPS` 增一项，条目 `group` 指过去 | 界面按 `ISSUE_GROUPS` 顺序渲染；分组不参与逻辑判断 |
| 调整上限 | 改 `ISSUE_LIMIT` | 界面计数与拦截都读这个常量 |
| 查各分组条数 | `ISSUE_COUNTS`（预计算的 `Record<IssueGroup, number>`） | 界面分组标题右侧的数字来自它 |

**写 `adapt` 的约束**：一句话说清"这节课要改什么"，用可执行的动作。不要写「关注学生差异」
这类无法落地的原则；涉及学生身份（民族、家庭结构）时，不得让个体代表整个群体，
措辞要走"征得同意、并置比较"的方向。`prep` 只在确实需要额外准备时才写。

### 2.5 自检清单

改完预设后跑一遍（或人工核对）：

- [ ] `ISSUE_PRESETS.length` 与 `ISSUE_COUNTS` 各分组之和一致
- [ ] 所有 `id` 唯一
- [ ] 每条都有非空 `adapt`，长度足够形成一句完整的话
- [ ] 每条 `group` 都能在 `ISSUE_GROUPS` 里找到
- [ ] 界面分组标题的数字与实际胶囊数一致
- [ ] 选中 2-4 条后生成的方案，能在「教学准备」看到 `prep`、在「教学提示」看到 `adapt`

## 三、两者交叠处

Word 导出的「课程信息表」有一行 `学情预设`，内容来自 `issuesLabel(plan.input.issues)`，
即所选预设的 `label` 用顿号连接。**改 `label` 会改变已导出文档上的这一行**（重新导出时），
所以 `label` 应保持简短（4-8 字），避免信息表被撑开换行。

## 四、课程主体的两张表

这是全站的地基，也是最容易改错的地方。**课程是主体，学科是落点**，
两张表分别承担"这门课有哪些知识点"和"每个知识点能落到哪门课的哪个教学内容"。

### 4.1 分工

| 表 | 文件 | 规模 | 职责 |
| --- | --- | --- | --- |
| 知识点（`KnowledgePoint`） | `src/data/curriculum.ts` | 10 章 26 单元 **73 个** | 章节、单元、标题、摘要、核心问题。**不存任何学科字段** |
| 知识卡（`KnowledgeCard`） | `src/data/knowledgeCards/ch1..10.ts` | **73 张**（一对一） | 核心要点、关键概念、常见误区、课堂追问 |
| 迁移落点（`SubjectPointLink`） | `src/data/subjectPoints.ts` | **164 条** | `[pointId, subject, use, why]`，`use` 是用法，`why` 点名落到哪个教学内容 |

**为什么学科字段不放在知识点上**：一个知识点会被多门课用到（如"城市化与社区认同"同时落到
道德与法治、综合实践），把学科写成 `KnowledgePoint` 的数组字段会立刻产生两份真相，
且新增学科要改动 73 条记录。放成独立映射表，一条关系一行，加学科只是加行。

### 4.2 关键约束

1. **章节归属一律派生**。用 `chapterIdsOfPoints(pointIds)` 从知识点反查章节，不要手写 `chapterIds` 数组。
   跨章资源会在各章都出现，全局计数按 `key` 去重（`verify.mjs` 就是这么算 247 的）。
2. **双索引是唯一数字来源**：`SUBJECT_INDEX`（按学科）与 `CHAPTER_INDEX`（按章）。
   界面上任何"共 N 条"都必须取自它们或 `AUX_SCALE`，不许在组件里 `filter().length` 现算。
3. **空态合法**：某学科可借 0 个知识点是必须存在的界面状态（数学、英语等以学科本体为主的科目），
   文案是"本科以学科主线备课即可"，不是缺料警告。学科总览、资源库、工坊三处都要有对应措辞。
4. **`use` 的取值只有四种**，定义在 `src/lib/types.ts` 的 `PointUse`：
   `context`（情境导入）/ `material`（素材案例）/ `contrast`（对比辨析）/ `extension`（延伸阅读）。
   它们表达的是"这个知识点以什么方式服务学科"，不是知识点的分量排序。
   展示顺序读同一文件的 `USE_ORDER`；新增枚举值必须同时进 `USE_ORDER` 与 `POINT_USE_LABEL`，
   否则该条会在界面上静默消失（类型检查不会报错，因为 `Record` 只在漏 `label` 时才拦得住）。

### 4.3 生成路径（已废弃，仅存历史）

本节原描述 `src/lib/agent/engine.ts` 的三条规则拼装路径（`folk` / `point` / `subject`）。该文件已于
2026-11-04 删除，站点只剩 AI 一条生成路径，提示词里也没有「民俗」这一层。现行口径见
`docs/change-ai-only-apply-studio.md` 与 `docs/change-material-unified-subject-choice.md`。

仍然成立的一条经验：**提示词的锚点必须中性**。学科本体课不该出现「民俗」「知识点」「章节」这类
辅助层词汇——改提示词后建议抽一份学科主线的方案，通读正文确认没有这类泄漏。

### 4.4 改完必跑

```bash
npm run verify   # 两张对账表 + 资源池一致性
npm run build    # tsc --noEmit && verify && vite build
```

`verify` 会打两张表并校验：所有 `pointId` / `cardId` 无悬空、每章有卡片、每张卡都有对应知识点、
学科↔知识点条数与表长一致。当前的基线数字：

- 资源池 **247**（知识点卡 73 · 教学素材 136（图文条目 60 · 媒体素材 76）· 课例 38）
- 图文条目 ↔ 知识点 **263** 条
- 学科 ↔ 知识点 **164** 条

数字变了要么是数据真的改了（那就同步本文件），要么是派生逻辑坏了（那就修逻辑，别改数字）。

## 五、界面自检：375px 横向溢出

`scripts/overflow-check.mjs` 用本机 Chrome 无头 + CDP 实测，不装任何依赖。

```bash
npm run dev -- --port 5178 --strictPort   # 另开一个终端，脚本按这个端口取页面
node scripts/overflow-check.mjs
```

判定标准只有一条：`document.documentElement.scrollWidth > clientWidth`（允许 1px 取整）。
元素清单仅作定位——横向滚动容器里的子元素正常越界，不算问题。

注意两点，否则会得出错误结论：

- **必须用无头 Chrome 的移动视口**（脚本已设 375×812、`mobile: true`）。桌面缩窗口不会触发移动端断点。
- **路由参数不要从 Bash 直接传**。Git Bash 会把 `/subjects` 当成路径改写成 `C:/Program Files/...`，
  脚本就打开 404 页、一致报"无溢出"。要么像现在这样把路由写死在脚本里，
  要么传参时加 `MSYS2_ARG_CONV_EXCL='*'`。

已修过的真实问题：`/resources` 的主栏是 `grid` 子项，默认 `min-width: auto`，
内容最小宽度 410px 把整列顶出视口 51px。修法是给内容列加 `min-w-0`（已加并留了注释）。
**凡 grid/flex 子项内含 `truncate`、长串或横向滚动区，都要显式给 `min-w-0`**，
这是本项目在窄屏下唯一反复出现的溢出成因。
