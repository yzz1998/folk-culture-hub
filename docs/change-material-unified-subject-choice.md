# 功能改造说明：素材统一归类 · 教学应用自选学科 · 工坊移除民俗素材

> 适用版本：2026-11-04 之后的工作副本
> 涉及路由：`/resources`（重写）、`/resources/material/:id`（新建）、`/apply`（改造）、`/agent`（第 2 步清理）
> 一句话：**资源只有三类，教学素材按章节归位；教学应用里每张卡自带学科选择；工坊的已选材料只剩知识点与媒体素材。**

---

## 一、资源库：不再区分「民俗条目」与「教学素材」

### 1.1 新的资源口径

| 层面 | 改前 | 改后 |
| --- | --- | --- |
| 资源种类 | 知识点卡 / 民俗条目 / 教学素材 / 课例（四类） | **知识点卡 / 教学素材 / 课例**（三类） |
| 民俗条目 | 独立一类，有自己的图标、详情页、筛选口径 | 并入教学素材，形态为 `entry`（图文条目） |
| 分类维度 | 以「民俗 / 素材」区分为主，章节只是筛选之一 | **章节是唯一分类维度**；章内再按知识点分堆 |
| 素材形态 | 混在「教学素材」里，靠图标分辨 | 显式的 `form`：图文条目 / 图片 / 音频 / 视频 / 文本资料 |
| 章节归属 | 民俗条目手工挂章节，素材另算 | 一律由 `pointIds → chapterIdsOfPoints()` 派生，不手写 |

类型定义（`src/lib/catalog.ts`）：

```ts
export type ResourceKind = 'card' | 'material' | 'lesson'
export type MaterialForm = 'entry' | 'image' | 'audio' | 'video' | 'text'

export type ResourceItem = ResourceBase &
  ( | { kind: 'card'; data: KnowledgeCard }
    | { kind: 'material'; form: 'entry'; data: FolkItem }
    | { kind: 'material'; form: Exclude<MaterialForm, 'entry'>; data: Material }
    | { kind: 'lesson'; data: LessonPlan } )
```

`entry` 之所以仍保留自己的数据形状（`FolkItem`：有 `category` / `region` / `themes` / 正文段落），是因为它确实比其他素材多几层字段；**但对外它只是「教学素材」的一种形态**，界面上不再出现「民俗条目」这个词。

### 1.2 原民俗素材的迁移

| 迁移前 | 迁移后 | 说明 |
| --- | --- | --- |
| 60 条民俗条目 | 60 条教学素材 · 形态「图文条目」 | 一条不少；`id` 未改，旧收藏与旧链接仍然有效 |
| 详情页 `/resources/folk/:id` | `/resources/material/:id` | 旧路由保留重定向，历史分享链接不 404 |
| 筛选 `?kind=folk` | `?kind=material&form=entry` | 旧参数 `folk` 被识别为 `material`，不落空 |
| 收藏键 `('folk', id)` | 不变 | 收藏是用户数据，改键等于清零 |
| 关联知识点 263 条 | 不变 | 章节归属由这些关联反推，因此迁移后章节结构自动成立 |

迁移后资源总量与构成（`npm run verify` 输出）：

```
知识点卡 73 · 教学素材 136（图文条目 60 · 媒体素材 76） · 课例 38 · 合计 247
图文条目↔知识点关联 263 条 · 学科↔知识点 164 条
```

素材形态分布：图文条目 60 · 图片 60 · 音频 3 · 视频 7 · 文本资料 6。
十章条目数：ch1 66 / ch2 54 / ch3 55 / ch4 42 / ch5 65 / ch6 71 / ch7 87 / ch8 69 / ch9 36 / ch10 43。

**覆盖度核查**：10 章 73 个知识点，**每一个知识点都至少挂着一条可用素材**（缺 0 个）；其中 70 个知识点有图文条目，3 个目前只有媒体素材——这是后续补料的确定清单，不是结构问题。

### 1.3 分类结构在界面上如何呈现

`/resources` 自上而下四层，一一对应教师的查找路径：

1. **类型**：全部 / 知识点卡 / 教学素材 / 课例（附数量）
2. **形态**（仅教学素材视图出现）：全部形态 / 图文条目 / 图片 / 文本资料 / 音频 / 视频
3. **章节**：全部 + 10 个章节 chip——这是唯一的分类主轴
4. **落到哪门课**：全部学科 + 11 个学科，作为可选二级筛选

列表默认「按章节 · 知识点」分组：章标题下按知识点分堆，挂不到具体知识点的条目归入「本章综合」。跨章素材会在多章下重复出现（真实归属），因此顶部写明「共 N 条」按条目去重，与各章程条目之和不必相等。

顺带修掉一处口径不一致：学科 chip 上的数字原先取全局资源数，切到「教学素材」后仍显示 247，与右侧「共 136 条」对不上。现在学科 chip 的计数改为**按当前类型 / 形态的底表实时统计**，「全部学科」显示 136，语文 122、数学 13……与列表同源。

## 二、教学应用：每张卡的 AI 分析可自选学科

### 2.1 改前的问题

卡片只认平台登记的落点：英语老师想看某个知识点能不能用进自己的课，如果登记表里没写「英语」，连分析的入口都没有。登记表是「常见用法」，被当成了「允许清单」。

### 2.2 改后的规则

| 层面 | 改前 | 改后 |
| --- | --- | --- |
| 分析对象 | 页面筛选的学科，或该知识点已登记的第一个学科 | **每张卡自己选**，收起时显示当前对象，展开后铺开全部 11 个学科 + 「不限」 |
| 未登记学科 | 不可选 | 可选。卡片给一句说明：「还没有登记落点，结果由 AI 现找——接得上就有具体用法，接不上会直说」 |
| 页面「我的学科」 | 筛选门槛（会过滤掉卡片） | **默认分析对象**，不再是门槛；切换它，卡片跟随 |
| 只显示有落点的点 | 默认行为 | 「只看已有落点」开关，默认关 |
| 缓存 | 按知识点缓存一份 | 按 `analysisKey(pointId, subject)` 缓存，**一科一份** |
| 换学科 | 无此动作 | 立即按新学科重取；该学科已有结果则直接复用，不重复消耗 token |
| 提示词 | 「只允许在已登记学科内作答」 | 「教师指定的学科就是本次分析对象，与平台有没有登记过无关……确实接不住就直说并说明原因」 |

关键实现（`src/components/apply/PointApplyCard.tsx`）：

```ts
/** 缓存键：一个知识点 × 一个分析对象（null 表示不限学科） */
export function analysisKey(pointId: string, subject: Subject | null): string {
  return `${pointId}|${subject ?? ''}`
}
```

`useEffect` 只依赖 `target`：换学科即重取，收起不清缓存，再点开直接显示上次结果，要新的点「重新分析」。每张卡独立展开，便于横向比较同一知识点在不同学科里的用法。

### 2.3 交互流程

```
进入 /apply
  → 页面级「我的学科」+ 任教年级作为默认值（可留空 = 不限）
  → 卡片收起：标题 / 摘要 / 已登记落点标签 / 「分析对象：语文 ⌄ 可换任意学科」
  → 点「AI 分析」：展开 → 出现学科 chip 行 → 首次请求（骨架屏，通常 5–15 秒）
  → 结果分四段：能落到哪些课堂 / 三步落地 / 容易上歪的地方 / 留给学生的追问
  → 在 chip 行换「英语」：结果区立即换成英语那一份（未登记时前端先给一句说明）
  → 点「带它去备课」：跳 /agent?point=<id>&subject=<所选学科>，落点已带过去
```

四类失败各有出口，不写「分析失败」了事：未配置 → 「去设置接入」；鉴权失败 → 提示 Key 无效；网络 / 超时 → 报具体原因并可重试；返回格式不符 → 提示重试或换模型，**不展示半成品**。

## 三、工坊：已选材料里不再有「民俗素材」

本系统面向《人类与社会》课程，不是民俗专题站。工坊第 2 步原有的「民俗素材」选择区已整体删除。

| 层面 | 改前 | 改后 |
| --- | --- | --- |
| 输入结构 | `AgentInput.folkIds: string[]` | 字段删除，类型同步收紧 |
| 第 2 步界面 | 知识点区 + 民俗素材区（独立勾选区） | **只有知识点区**；右侧已选材料分「知识点 / 教学素材」两类 |
| 教学素材来源 | 手工勾选民俗条目 | 由已选知识点自动带出**可直接投屏的媒体素材**（图片 / 音频 / 视频），图文条目在资源库里留着备课参考 |
| 已选计数 | 知识点 + 民俗 + 素材 | `pointIds.length + materialIds.length` |
| 生成载荷 | `folkIds`、`folkLink` | `folkIds: []`、`folkLink: 'none'`（提示词不再拼接民俗段落） |
| 导出 / 空间 / 结果卡 | 读 `folkIds` 拼素材标签 | 读 `materialIds` + `MATERIAL_MAP` |

一致性核查（已执行）：

- `grep folkIds src/` 只剩 `data/lessons.ts` 中课例自身的素材引用字段，`AgentInput` 与工坊状态里已无此字段；
- `folkBlock` / `pair` / `THEME_EMOTION` 等提示词片段已删除，改为统一的 `materialBlock`；
- 第 2 步实测文案：「全书 73 个知识点都可以选，不限章节、不限学科已登记的范围。『语文』已有 31 个常见落点，只作提示，不影响可选范围。」——无常驻的民俗选择区；
- 右侧「已选材料（0）」下只有「知识点 0」「教学素材 0」两栏，空态文案为「选知识点，这里会列出可直接投屏的素材」。

## 五、遗留与建议

1. **3 个知识点缺图文条目**（仅有媒体素材）。补 3 篇图文即可让 73 个知识点全部「有得读」，是本轮之后最值得做的一件小事。
2. **第 4、8、9 章课例偏少**（各 1 份），校验脚本已持续提示。
3. `/resources` 的「类别 / 主题 / 地域」三个细项筛选项仍只作用于图文条目（媒体素材没有这些字段）。目前界面已注明，若日后媒体素材也要按主题筛，需要给它补 `themes` 字段，而不是放宽现有判断。
4. 资源卡封面目前是统一的 SVG 占位图，图文条目与图片素材看起来一样。若要做视觉区分，建议给媒体素材加角标（如「可投屏」），比换封面成本低。
