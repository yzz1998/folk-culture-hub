# 信息架构：课程为主体，迁移为出口

本文件是站点的组织原则。改任何页面之前先读这里，否则很容易把「学科主轴」的旧结构长回来。

## 一句话

《人类与社会》是主体，知识点是最小单位，**教学应用**是把知识点接到小学课堂的出口。
民俗不进主线——它是第 7 章「宗教与民俗」里的一类内容。

## 四层

| 层 | 规模 | 承载页面 | 说明 |
| --- | --- | --- | --- |
| ① 课程主体 | 10 章 / 26 单元 / 73 知识点 | `/curriculum` 课程脉络 | 平台的地基。资源和教案都从这里派生章节归属 |
| ② 知识点 | 73 张知识卡 | `/resources/card/:id` | 要点 / 概念 / 误区 / 追问，四段可直接搬进课堂 |
| ③ 教学应用 | 164 条落点 | `/apply` 教学应用 | 「这个点能落到哪门课的哪个教学内容、起什么作用」 |
| ④ 你的课堂 | — | `/agent` 备课工坊 | 选学科 → 全书任选知识点 → 定学情 → AI 生成，导出 Word |

民俗（60 条）挂在第 7 章下，与知识卡、教学素材、课例并列。它有页面、有入口，
但**没有一级导航、不在首页主线、不是配色与纹样的来源**。

## 导航

```
首页 → 课程脉络 → 资源库 → 教案库 → 教学应用 → 智能备课工坊 → 我的空间
```

顺序即口径：先课程，后资源，再落点，最后备课。
移动端 5 个标签：课程 / 资源 / 工坊（主）/ 应用 / 我的。

旧链兼容：`/subjects → /apply`、`/materials → /resources?kind=material`、`/folk → /resources`。

## 每页只回答一个问题

| 页面 | 只回答 |
| --- | --- |
| 首页 | 这门课讲什么、怎么用、从哪开始 |
| 课程脉络 | 这一章这一单元讲了什么，这个点能落到哪 |
| 资源库 | 这一章有哪些可用材料（三类资源，按章节归位） |
| 教案库 | 别人怎么把它迁移进课堂 |
| 教学应用 | 这个点能落到哪些课堂；按我的学科，具体怎么用 |
| 备课工坊 | 给我这个点 + 这门课，AI 产出一份能改的教案 |

页面一旦想同时回答两个问题，就会出现「学科总览 vs 课程地图」那种打架局面。

## 数据层：两张表，两种视角

| 表 | 文件 | 规模 | 视角 |
| --- | --- | --- | --- |
| `KnowledgePoint` / `KnowledgeCard` | `data/curriculum.ts`、`data/knowledgeCards/` | 73 / 73 | 课程主体 |
| `SubjectPointLink` | `data/subjectPoints.ts` | 164 | 迁移落点 |

`SubjectPointLink` 的字段是 `[pointId, subject, use, why]`：

- `use`：以什么方式用上——情境导入 / 素材案例 / 对比辨析 / 延伸阅读（`USE_ORDER` 定顺序）
- `why`：落到这门课的**哪个具体教学内容**、起什么作用。必须点名内容，不能只写"可作素材"

**方向不可写反**：一条映射的主语是知识点，学科是宾语。「这个点能落到语文的复述训练」
而不是「语文借用了这个点」。所有界面文案都遵循这个方向。

`KnowledgePoint` 上**不存任何学科字段**——一个点会被多门课用到，存成数组立刻产生两份真相。

## 三条硬约束

1. **章节归属一律派生**：`chapterIdsOfPoints()` 从知识点反推，不手写 `chapterIds` 数组。
   跨章资源在各章都出现，全局计数按 `key` 去重（`npm run verify` 就是这么算 247 的）。
2. **数字只来自 `catalog.ts`**：`COURSE_SCALE` / `RESOURCE_COUNTS` / `SUBJECT_INDEX` / `CHAPTER_INDEX`。
   页面里不许 `filter().length` 现算，否则同一件事会出现两个数字。
3. **空态合法**：某门课可承接 0 个知识点是必须存在的界面状态（英语、信息科技本就如此）。
   文案是「按自己的主线备课即可」，不是缺料警告。课程脉络、教学应用、工坊三处都要有对应措辞。

## 备课工坊的四步

```
① 定落点（只选学科，不限定知识点范围）
→ ② 选知识点（全书 10 章 73 个任选，最多 3 个，可整段跳过）
→ ③ 定课程与学情（主题必填）
→ ④ AI 生成方案
```

第 ① 步只回答「这节课落在哪门课」，**不决定能从课程里拿什么**——`subjectPoints` 登记的是
常见落点，不是允许清单，所以第 ② 步的范围是整门课，不按学科过滤。

跳过第 ② 步仍能生成：不借任何知识点时，方案按学科主线写，提示词里会明确「不要虚构民俗、
不要硬拉课程概念」。

## AI 是唯一引擎

本地组装引擎已移除（`lib/agent/engine.ts`、环节模板与三路径校验脚本一并删除）。
现在的规则只有一条：**没有 AI 就不生成**。

- 未配置 → 生成按钮可用，点击后给出原因并链到设置；不静默降级
- 失败（超时 / 鉴权 / 格式）→ 保留条件，显示原因与重试
- 模型漏字段 → 结构性补齐（空串 + note 提示），不代写正文

`lib/agent/llm.ts` 是唯一出口：`generatePlanWithAI`（整课）与 `analyzePoint`（单点分析，
在 `lib/agent/analyze.ts`）共用同一个 `requestJson`。

## 改版时最容易犯错的三处

1. 把「学科」重新当成第一层组织维度（会立刻与「课程主体」冲突）。
2. 让民俗回到装饰位（品牌纹样、首页时令推荐、空态插画），基调就又被带偏了。
3. 在组件里另算一套数字，`verify` 未必报错，但页面之间会对不上。
